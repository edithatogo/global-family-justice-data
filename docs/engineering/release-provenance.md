# Release provenance and integrity

## Deterministic release tree

A draft release is assembled from an explicit public input surface, generated catalogue and programme products, public data products, validation results and lineage. With identical repository inputs, version and `SOURCE_DATE_EPOCH`, the builder must produce a byte-identical ZIP archive.

## Integrity layers

The release has several independent layers:

1. `MANIFEST.sha256` covers every bundled file except itself.
2. `RELEASE.json` records version, release class, epoch, contracts, gate, counts, validation and known limitations.
3. `SBOM.spdx.json` records declared Python dependencies in SPDX 2.3 form.
4. `provenance/lineage.csv` connects released observations to source edition, extraction, transformation, review and exact locator fields where those records exist.
5. `provenance/build-attestation.json` is an in-toto Statement v1 using the SLSA provenance v1 predicate shape.

The attestation subject is a SHA-256 digest over the sorted path-and-digest set of the deterministic pre-attestation release tree. `RELEASE.json`, the SBOM, the manifest and the attestation itself are excluded from that subject so the attestation can be created without a circular hash.

## Verification

```bash
SOURCE_DATE_EPOCH=1784419200 gfjd release build \
  --version 0.4.0-alpha.1-rehearsal \
  --output build/rehearsal \
  --source-date-epoch 1784419200

gfjd release verify \
  build/rehearsal/gfjd-0.4.0-alpha.1-rehearsal
```

Verification independently checks manifest syntax and path safety, required artifacts, missing and extra files, every file digest, release schema, SBOM minimum structure, attestation schema and the recomputed attestation subject. Rewriting the attestation and updating only the manifest therefore does not conceal a modified release tree.

## Trust boundary

The current attestation is generated by the repository builder and is not cryptographically signed. It proves consistency between a release tree and a declared build record; it does not prove the identity or independence of the builder. Stable v1 requires protected release authority, immutable CI action pinning, externally verifiable signed provenance, credential recovery/revocation and archival custody outside the primary repository host.
