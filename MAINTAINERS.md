# Maintainer roles

Names and institutional contacts must be added before public beta. Roles, not individuals, own the obligations below.

| Role | Accountabilities | Required deputy |
|---|---|---|
| Executive sponsor | Institutional authority, resources, independence safeguards | Yes |
| Project director | Scope, programme delivery, stakeholder accountability | Yes |
| Methods chair | Ontology, comparability, quality rules, methods decisions | Yes |
| Data steward | Data contracts, lineage, release data approval | Yes |
| Engineering lead | Architecture, CI, reproducibility, dependencies | Yes |
| Security and privacy lead | Threat model, incidents, disclosure controls | Yes |
| Release manager | Candidate builds, readiness evidence, tag/archive | Yes |
| Operations lead | Monitoring, backups, corrections, support | Yes |
| Regional/language leads | Search quality, local review, translation | Yes for critical regions |
| Lived-experience/child-rights chair | Safe and meaningful advisory participation | Yes |

No person may alone approve and execute a production release. Methods/data approval and release execution require separation of duties.
