# Changelog

All notable changes to this project are documented here.

## [0.3.0] — 2026-07-19

### Added

- evidence-driven programme conductor covering ten tracks, six gates, work, evidence, maturity, risks, defects, exceptions and formal decisions;
- atomic programme-state mutations with advisory locking and JSONL before/after audit events;
- 12 executable data contracts and expanded jurisdiction, institution, matter, source-edition, extraction, review and outcome-evidence schemas;
- rights-aware local/HTTP acquisition, checksum verification and safe public-network defaults;
- configurable observation mapping, reason-coded quarantine, gold promotion and lineage generation;
- deterministic release builder with stable-release gate interlock, manifest, SBOM, verification and release diff;
- integrated CLI, multi-version CI, CodeQL and critical-path tests;
- implementation status, v1 gap analysis, conductor architecture and operations runbook.

### Changed

- the current baseline is explicitly v0.3 engineering infrastructure before G1, not a completed programme release;
- v1 progression is based on accepted evidence and formal decisions rather than document presence or elapsed time;
- roadmap versions now align with machine-readable gate targets.

### Fixed

- impossible gold-promotion state caused by a mismatch between the observation schema and promotion rule;
- deterministic release status generation;
- acquisition manifests now include every required contract field.

## [0.2.0] — 2026-07-19

### Added

- integrated 24-month roadmap with ten workstreams and six evidence gates;
- binding v1.0 release criteria and no-go conditions;
- evidence-based maturity model from concept to stable service;
- detailed track charters, delivery backlog, risk register and scorecard template;
- v1 architecture, quality, operations, RACI, security and compatibility plans;
- release and gate evidence templates;
- matter-type ontology seed, outcomes evidence template and review ledger template;
- JSON schemas for matter types, outcomes evidence and release metadata;
- deterministic repository manifest tooling and stronger repository validation;
- multi-version CI, correction issue template and pull-request checklist.

### Changed

- v1.0 is now defined as a stable, independently assured and funded public-data service rather than merely the first global census publication;
- README, project plan, governance and contribution guidance align with the v1 hardening path;
- package version advanced to 0.2.0.

### Removed

- generated Python and pytest cache files from the distributable repository.

## [0.1.0] — 2026-07-19

- initial project plan, seed registers, methods documents, schemas and basic validation scaffold.
